SCC OPERATOR FIELD GUIDE / SOURCE-BOUND

From a coding request to defensible evidence.

CODEMIND coordinates method selection and Serena source intelligence. Deployment, worker execution, and final delivery must be proved separately. This guide explains what operators can do now and what the final Codex deployment requires.

Current guide is a design/operations reference, not a live host health monitor. No green claim is derived from this page alone.

01

How-To: choose the least-friction path

Reuse existing CODEMIND routes and tools before creating a new worker, process, or endpoint.

  1. Bind the source and task

    Identify the user goal, active workspace, source generation, permitted files and acceptance criteria. Recheck the workspace before any mutation; the active Serena project can change between calls.

  2. Route once, deterministically

    Run codemind_skill_route against trusted codemind- manifests. Record selected methods and why. Metadata matching makes no LLM call for metadata routing; open-ended diagnosis and repair can still require reasoning.

  3. Inspect, then formulate the smallest fix

    Prefer Serena symbols, references, and diagnostics over unrestricted whole-project scans. A selected skill is not an invoked executor: selected ≠ loaded ≠ executed.

  4. Apply only an authorized change

    The provider must enforce operation-level approval, exact workspace, current revision and durable effect identity. Hooks are supplementary guardrails, not the final permission boundary.

  5. Freeze source, queue independent checks

    Use a real host-owned queue with at most three active Codex subagents, admission/backpressure, terminal-state observation, process-tree cleanup, and immediate slot recycling. A mock worker pool is not this capability.

  6. Prove the outcome

    Review the precise diff and run syntax, affected tests, negative cases and runtime proof where requested. Timeout, skipped validation, source-only hooks, or an advisory packet cannot be recorded as successful completion.

Route selected: incremental native integration. Keep the existing CODEMIND dashboard, skill registry and semantic methods. Add host verification and a queue adapter only after its owning API is known and independently tested. Avoid a second orchestrator and premature deployment buttons.
02

Five non-negotiable Codex readiness gates

All five require fresh host evidence. This page does not auto-approve any gate.

G1 — Trusted hooks

NOT VERIFIED

Codex .codex/hooks.json is installed, reviewed/trusted by its hash, activated, and observed firing through supported events. A source configured is not host trusted.

Proof: host /hooks inspection + real event receipt + negative test.

G2 — Serena indexing

NOT VERIFIED

Exact project root and generation are pinned. Enabled language servers initialize; representative file/symbol/reference queries return current results.

Proof: project identity + current language diagnostics + actual symbol read.

G3 — File-type coverage

NOT VERIFIED

Every encountered extension has an explicit capability map: semantic handler, safe text/structured fallback, binary metadata-only route, or denied operation. Registering a type is not the same as semantic LSP support.

Proof: enumerated project extensions and tested routing for supported/unknown/binary types.

G4 — Three-slot subagent scheduler

NOT IMPLEMENTED

Host-controlled atomic slot leases cap active actual Codex subagents at three, with bounded queue, cancellation, orphan reconciliation, process cleanup and verified vacancy recycling.

Proof: host integration exercises concurrent admission, completion, crash, timeout and memory reclamation.

G5 — Governance and delivery

NOT VERIFIED

Task-scoped authorization, source revision fencing, effect journal, focused regressions and installed-to-running-version parity all pass. Learning remains candidate-only without governed promotion.

Proof: provider denial tests, deterministic replay, source SHA, acceptance receipt.

Deployment formula: G1 + G2 + G3 + G4 + G5 must all be independently verified. One unverified gate means NOT READY for autonomous Codex deployment; read-only advisory features may remain useful.

Scenario playbooks

Find the matching situation, run only what is currently authorized, and preserve the required proof.

Showing all scenarios and FAQs.

Bug fix — repeating API error

Prompt: “Locate the observed error, inspect the owning symbol, patch only the affected behavior and run its regression test.”

Route: deterministic bug triage → Serena symbol/references → falsifiable test → bounded authorized patch → verification barrier.

Completion: observed failing case becomes green at a recorded source SHA; no skipped or stale tests.

Feature implementation — new settings control

Route: confirm UI/API contract → inspect existing component and endpoint → add one scoped interaction → test invalid and successful responses → verify responsive/keyboard behavior.

Completion: usable control, correct network effect, error handling, no unrelated state mutation. Design-only mockups are not deployment proof.

New file type — unknown extension in the project

Route: classify the extension; check registered Serena language handler; otherwise use a named read-only fallback or deny unsupported edits. Never disguise text search as semantic indexing.

Completion: file-type table, matched provider, negative unknown/binary cases and representative read.

Hook installation — Codex says nothing is firing

Route: verify the trusted repository .codex/ layer, inspect Codex /hooks, review changed hashes and execute a harmless real event. No bypass of trust review.

Completion: observed event receipt under exact session and version, not just a JSON file on disk.

Subagent queue — five validation jobs, three slots

Expected: admit three real Codex agents maximum; hold two queued. When an agent terminates, confirm child cleanup and release its lease before dispatching the next job. The builder does not run heavy tests concurrently.

Completion: peak-active ≤ 3, no double lease or orphan work, complete receipts and bounded memory.

Regression failure — failed verification or validation timeout

Route: mark timed-out verification UNKNOWN, reconcile uncertain side effects, inspect relevant diagnostics and change hypothesis before bounded retry. Do not silently relaunch the identical operation.

Completion: a fresh passing run of the affected tests, or explicit BLOCKED status.

Learning — repeated issue across tasks

Route: sanitize evidence, deduplicate failure fingerprints, test a proposed guard against counterexamples, keep the candidate quarantined and require governed promotion.

Completion: an assessed candidate or approved versioned lesson—not unauthorized skill execution or new permission.

04

Frequently asked questions

Specific answers for operators, testers and reviewers.

Does selecting a CODEMIND skill run it?

No. Selection is a deterministic match. Loading instructions and actually executing an authorized tool are separate events, each with its own evidence.

Can SCC automatically repair a bug with zero tokens?

Classification can use no model calls. Novel source diagnosis, implementation choices and review may still require reasoning and model tokens. A scripted known transformation can be deterministic only within its tested contract; not the same as an autonomous repair.

Does Serena register every possible file type?

No language server understands every format. CODEMIND must classify project files and route them to an explicit semantic handler, safe fallback or denial. Unsupported semantic operations remain unavailable.

Can SubagentStart alone enforce the three-slot limit?

No. A lifecycle hook observes an event; it does not guarantee an atomic host-wide admission lease, crash recovery or resource reclamation. The scheduler must own actual agent launch and cleanup.

Do configured hooks prove host activation?

No. Confirm project trust, hash approval, supported events and actual callback receipts. Hook timeouts and unsupported tool paths cannot be treated as fail-closed authorization.

How do I handle multiple active projects?

Bind each task to an immutable canonical root and version. Before each write, check target ownership and current source identity at the executing provider. A switched global Serena project must not redirect a task.

What happens when a reviewer detects an unrelated edit?

Stop the delivery gate, isolate the intended diff, preserve foreign changes and rerun affected checks on the reconciled source. Do not force-reset the workspace.

Are 25 reference methods equivalent to 25 working agents?

No. Reference methods, enabled skill manifests and deployed subagents are different capabilities. A catalog count is not a worker count.

What if a capability is unavailable or verification fails?

Report the exact missing evidence and affected gate as NOT VERIFIED or BLOCKED. Continue safe independent tasks; never convert advisory plans, mock workers or old test receipts into deployment success.

About SCC / CODEMIND

One governed engineering control plane, not a collection of competing runtime controllers.

CODEMIND SCC

The task and method control plane: goal, skill routing, authorization barriers, evidence and candidate learning. For Codex it must bind hooks, file-type handling and subagents only through tested host contracts.

Serena semantic engine

Source indexing, named symbols, references and diagnostics. The selected project’s configured language servers determine real semantic support.

Windows Commander

An independent external service; it is not a subagent slot, CODEMIND's scheduler, or implicit permission to execute processes.

CODEMIND method library

Versioned and trusted project skill manifests under .codemind/skills/. Metadata routing is advisory until a real host tool performs an authorized operation.
